# Кодовые имена · Картинки

Онлайн-аналог «Codenames: Pictures» для браузера. Полностью статический сайт —
разворачивается на GitHub Pages без сборки, бэкенда и ключей от сервисов.

**Играть: https://xpesh01.github.io/codenames-pictures/**

## Как играть

1. Один игрок жмёт **Создать комнату** и отправляет остальным ссылку (кнопка «Скопировать ссылку»).
2. Остальные открывают ссылку и жмут **Войти** — код уже подставлен.
3. Каждый выбирает команду (красные / синие) и роль:
   * **капитан** видит ключ — какие картинки чьи;
   * **оперативник** видит только поле и кликает карточки.
4. Капитан даёт подсказку: слово + число. Оперативники открывают картинки,
   пока не ошибутся, не закончатся попытки или не нажмут «Завершить ход».
5. Открыли убийцу — моментальное поражение.

Есть и режим **на одном экране**: переключатель «Показать ключ» прячет и
показывает расклад, устройство передаётся по кругу.

Раскладка поля: 5×4 (8 агентов у начинающей команды, 7 у второй, 4 нейтральных,
1 убийца) либо 5×5 для более длинной партии.

## Картинки

Иллюстрации генерируются процедурно: фон-градиент, геометрический узор и
комбинация из нескольких эмодзи в случайной композиции. Благодаря этому нет
зависимости от внешних ресурсов и вопросов с правами на изображения, а комбинации
практически не повторяются.

## Как это работает без сервера

GitHub Pages отдаёт только статику, поэтому игроки соединяются напрямую по
WebRTC через [PeerJS](https://peerjs.com/) — публичный брокер нужен лишь для
«рукопожатия», сами данные идут peer-to-peer.

Создатель комнаты — хост: у него живёт настоящее состояние игры, он проверяет
ходы и рассылает каждому игроку персональный срез. Оперативникам ключи
нераскрытых карточек не отправляются вообще, так что подсмотреть их в консоли
браузера нельзя.

Следствие такой схемы: **вкладка хоста должна оставаться открытой** всю партию.
Если хост ушёл — создавайте комнату заново.

## Деплой на GitHub Pages

Сайт публикуется прямо из ветки: **Settings → Pages → Deploy from a branch → main / (root)**.
Сборки нет, поэтому каждый пуш в `main` сам обновляет страницу через минуту-другую.
Файл `.nojekyll` уже в репозитории, так что Jekyll ничего не трогает.

Если хочется деплой через GitHub Actions, добавьте стандартный workflow с
`actions/upload-pages-artifact` (`path: .`) и переключите источник на **GitHub Actions**.
Для пуша файлов в `.github/workflows/` токену нужен scope `workflow`:
`gh auth refresh -s workflow`.

## Локальный запуск

Проект использует ES-модули, поэтому `file://` не подойдёт — нужен любой
статический сервер:

```bash
python -m http.server 8000
# затем откройте http://localhost:8000
```
